# 第四批：可复现证据与独立评测（执行记录）

本文件记录第四批评审意见的执行情况，明确**做了什么、受什么限制没做、待谁来做**。

## 1. 已做（机器可自动化的部分）

### 1.1 独立评测集
- `eval/evalset.md`：5 组共 15 个测试场景（新闻 / 赛前 / 社交 / 改写 / 低信息），**与 few-shot 范文完全分离**。
- 每组都标注了"应达到"与"应避免的陷阱"（如：不虚构比分、不给赌博建议、未确认消息须标注）。

### 1.2 三配置对比脚本
- `bin/run_eval.py`：在同一模型、同一输入下跑 **raw / min / full** 三配置。
  - `raw` = 无 skill（空 system prompt）
  - `min` = 仅最小核心规则（无范文）
  - `full` = 完整 skill（规则 + few-shot）
- 记录每例：字符数、耗时、`finish_reason`、token、**自动陷阱检测**（禁止词命中 / 必需要素缺失）。
- 支持 `--tag` 以对比多个模型。

### 1.3 结果汇总
- `bin/summarize_eval.py`：读结果生成 raw/min/full 对比表，并**明确警告"更长 ≠ 更好"**。

### 1.4 盲评模板（交给真人）
- `eval/blind_review.md`：母语编辑打分表（5 项 × 1–5 分），已隐藏配置标签，含 5 个开放问题。

### 1.5 证据链
- `PROVENANCE.md`：输入清单、抽样策略、脚本/模型版本、人工修订、输出哈希。
- 明确声明：**303GB / 10GB 是原料规模，不是质量分数**。

## 2. 受资源限制，无法在此环境完成

### 2.1 母语编辑盲评（需真人）
自动化只能测"是否违反硬约束"，**测不出"自然不自然""事实对不对"**。这需要一位
越南语母语编辑按 `eval/blind_review.md` 打分。**未完成此步前，不得宣称"已完整评测"。**

### 2.2 跨模型对比（需多个可用端点）
本环境只有**一个**可用 LLM 端点（本地 Qwen，`qwen-3.8-27b-awq`）。托管端点
（DeepSeek）无独立 API Key，无法调用。因此未做跨模型对比。
`run_eval.py --tag <model>` 已预留接口，用户在有多端点时可直接跑。

### 2.3 这带来一个诚实的结论
单模型（本地 Qwen）上的 raw/min/full 对比，**只能说明"skill 在此模型上的增益"**，
不能推广到 GPT / Gemini / Kimi。README 中"已适配任意 OpenAI 兼容模型"应理解为
**接口兼容**，而非**效果已验证**。
